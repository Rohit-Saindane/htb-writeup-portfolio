## Step 2 - Initial Foothold

### MCPJam Inspector RCE (CVE-2026-23744)

We access the service on port 6274 (`http://devhub.htb:6274`). Reviewing the settings and metadata endpoints reveals:

```text
MCPJam Version: v1.4.2
```

Researching vulnerabilities in MCPJam Inspector v1.4.2 discloses **CVE-2026-23744** (*Unauthenticated Remote Code Execution in /api/mcp/connect*).

#### Vulnerability Analysis:
The `/api/mcp/connect` API is designed to allow developers to connect MCP Inspector to local Model Context Protocol servers. When an HTTP POST request is received at `/api/mcp/connect`, the server extracts the `command` and `args` parameters from the JSON body and spawns a child process using Node's `child_process.spawn()` without any authentication or input sanitization.

Crucially, the developer bound the MCP Inspector server to `0.0.0.0` (all network interfaces) instead of `127.0.0.1` (localhost), allowing external unauthenticated attackers to execute arbitrary system commands.

## Step 5 - Mitigations & Defensive Hardening

To remediate the vulnerabilities identified across the DevHub environment, system architects should implement defense-in-depth controls across development interfaces, process visibility, and internal APIs:

### 1. Network Interface Binding & MCP Service Hardening (CVE-2026-23744)
- **Bind Development Tools to Loopback:** Development and debugging tools (like MCP Inspector) must never listen on wildcard interfaces (`0.0.0.0`). Configure services to bind strictly to `127.0.0.1`.
- **Implement Robust Authentication:** Enforce session authentication, API tokens, or mTLS on all MCP management endpoints before allowing child process creation.
- **Upgrade MCPJam:** Update MCPJam Inspector to version ≥1.4.3 where input validation is enforced on server configuration arguments.

### 2. Protecting Process Credentials & Environment Isolation
- **Pass Tokens via Configuration Files or Environment:** Avoid passing authentication secrets (such as `--ServerApp.token`) via command-line arguments. In Linux, command-line arguments are visible to all users on the host via `/proc/<PID>/cmdline` and `ps`.
- **Enforce Hidepid Mount Option:** Mount `/proc` with the `hidepid=2` option in `/etc/fstab`. This prevents unprivileged users from viewing processes belonging to other users:
  ```text
  proc /proc proc defaults,hidepid=2 0 0
  ```

### 3. Securing Internal Management Microservices (OPSMCP)
- **Eliminate Dangerous Debug Backdoors:** Remove emergency credential dump endpoints (`ops._admin_dump`) from operational services. Secret recovery should occur via dedicated secrets managers (such as HashiCorp Vault or AWS Secrets Manager) rather than custom HTTP APIs.
- **Separate Microservice Privileges:** Avoid running internal HTTP daemons under the `root` user context. The OPSMCP service should execute under a dedicated unprivileged service account (`svc_ops`) with no access to `/root/.ssh/`.
